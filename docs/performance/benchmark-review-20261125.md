## Implemented changes from the power investigation

**Mail.** The silent-push worker observes each account’s retry deadline. A transient feed failure backs off exponentially from five seconds to five minutes, with a longer provider deadline taking precedence. The next window starts after the last account attempted, so a slow account cannot monopolize every push. Waiting for startup and running the feed pass share one deadline. Other app clients can share the account credential refresh. System expiration cancels the worker and releases its background assertion. Session and account publications wake the readiness check, replacing the 100 ms polling loop. Pending writes continue to use their existing durable queues.

**Transcription.** Both iOS background task handlers cancel their actual task on expiration. Cancellation reaches publisher reads, resumed audio conversion and the speech analyzer. An interrupted job can be retried without a terminal-failure strike. While a slice is being re-decoded, the previous checkpoint stays on disk. New checkpoints append words beyond the saved position, then the completed slice replaces its overlap. Legacy checkpoint migration writes the new file atomically before removing the old one. Parakeet jobs take turns across model loading and inference, including when the actor suspends. The Apple analyzer no longer needs to poll an expiration flag once a second.

**Calendar and memory.** Weather had an observable diagnostic string updated even when no forecast was available. It had no readers. Removing that publication leaves actual forecast, location and attribution changes observable. The Mail stress fixture now feeds samples directly into its existing in-memory store. It generates the same conversations and bodies. Only the temporary array of input samples was eliminated. The scale report also records end-of-measurement physical footprint alongside the original peak-RSS gate.

The [per-case measurements](scale-results/benchmark-review-20261125/power-fixes-comparison.json) preserve each gate verdict, raw component samples, workload counts and binary identity. On the pre-fix iPad Simulator, the one-day workload had 365.92 MiB peak RSS but 41.0 MiB physical footprint at inspection and 42.2 MiB peak physical footprint reported by vmmap. At 90 days, those figures were 722.30, 359.5 and 438.3 MiB. RSS and physical footprint use different accounting and sample points. Both are useful. The original RSS thresholds remain in force.

The 60,000 single-block text arrays grew **4.58 MiB**. The fixture's conversation dictionary grew **3.00 MiB**. Their combined increase was **12.58 MiB**. Allocated bytes and process physical footprint have different accounting. Actual arm64 value-layout measurements show the stride per message body grew from 80 to 120 bytes, per text block from 40 to 104 bytes, and per stored fixture conversation from 376 to 400 bytes. This fixture holds all the bodies in memory. A disk-backed mailbox needs its own open, cache eviction and reopen measurements.

### A candidate for reducing Mail body storage

An isolated arm64 Mac Release probe made two cases indirect in a copy of the current Swift contract: the designed-message body and picture text block. A plain paragraph then occupies a smaller value even when the app also supports rich HTML and pictures. With 60,000 retained synthetic bodies, the measured process footprint was:

| Bodies containing a designed document and a picture | Current representation | Experimental representation |
|---|---:|---:|
| 0% | 34.64 MiB | 19.05–19.06 MiB |
| 10% | 34.19–34.20 MiB | 20.16 MiB |
| 100% | 30.02–30.03 MiB | 30.11–30.13 MiB |

Both binaries checked the identity and contents of every body. Each mix ran in current / experimental / experimental / current order. Construction and lookup timings are retained with the samples. Their spread makes a speed claim premature. The experiment changes two enum cases together and uses the real Mail contract with synthetic content. The product code in the checkout retains the current representation.

To reproduce, compile the [probe](scale-results/benchmark-review-20261125/body-storage-probe/main.swift) with the current [Mail contract](../../Banana/Model/Mail/MailContract.swift) using optimized arm64 Swift on macOS under the repository build lock. For the second binary, compile a temporary copy of that contract with `indirect` before `case designed(document:` in `MailBody` and `case picture(MailPicture)` in `MailTextBlock.Kind`. The program takes the rich percentage as its sole argument. Run each binary with 0, 10 and 100, preserving the order above. Next, test the two cases separately on the disk-backed Mail path. Measure footprint, open time and scrolling with cold, warm and evicted bodies, including image-heavy and long documents, before changing the product.

### An idle-power signal to isolate

Two 68-second quiet intervals on the candidate's stock iPhone Calendar fixture used 0.065–0.079 CPU seconds, wrote 4 KiB per interval and recorded 684–686 process interrupt wakeups. The quiet intervals started after the redraw probe ended. In a separate control with the injected playback clock disabled and only two kernel reads per interval, Calendar recorded 225 and 226 interrupt wakeups in 22 seconds. The Simulator Settings app recorded 75 and 106 in the same duration, while using more CPU. Other Banana routes also showed about ten interrupt wakeups per second in shorter two-second observations.

This gives an interval to investigate. A process interrupt wakeup can come from timer delivery or another service. For attribution, compare an empty scene in the same app with normal initialization, then enable shared observers and diagnostics one at a time. Preserve a physical-device check for wakeups, energy and external charging power. The isolated Calendar fixture bypasses live provider startup.
