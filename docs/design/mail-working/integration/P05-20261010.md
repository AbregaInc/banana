# Mail index prerequisites — staged work, October 10

P05 is not complete. Retention rules, shared records and conversation summaries
are now in source; the live index/source is not implemented. The C0c app/test

The byte-identical tested rules and tests now live in
`Banana/Model/Mail/MailHoldRules.swift` and `BananaTests/MailHoldRulesTests.swift`.

of these new files are still pending.

`MailHoldRules.swift` implements MAIL-ENGINE 5.4 using Foundation Calendar for
month arithmetic and local-day boundaries, and an explicit set of durable claims.
It returns a retention reason rather than performing any deletion. No live store
calls it. It deliberately does not treat Inbox, Unread or Important as claims.
Compute the edge once per pass, outside any per-conversation loop.

The staged XCTest file passed 9 native Release tests (zero failures), including
127 nonempty claim combinations, exact edge equality/expiry, month-end/leap-day
clamping, local midnight across 23/25-hour days, and claim-label allowlisting.
This is correctness evidence, not app latency or release-readiness evidence.

`MailEngineTypes.swift` is now in source, with appendix A's records plus the
explicit display-date, recipient-summary and own-address fields needed by mapping.
The first staged typecheck omitted MailAuthRules and failed; the corrected typecheck
passed, with both logs retained. No actual index schema exists yet.

`ThreadSummaryRules.swift` now computes confirmed-message summaries, bounded
six-person author/recipient lists with true totals, unread/flags, and retention
claims. A kept (`vis = 4`) message stays readable beside live mail; unconfirmed
rows remain excluded even when there is no other message.
