# Banana's website

`site/` is the whole of bananatheapp.com, live since 18 Oct 2026: the front page (HTML with its
own styles and one script that draws and animates the calendar scene), the Privacy Policy, Terms,
fonts and images. No runtime framework. Blog posts are generated from Markdown; what is in the folder is what is served.

| File | What it is |
| --- | --- |
| `site/index.html` | The front page: copy, styles and the scene's script in one file. The scene is written finished; the animation only hides each piece until its moment, so with reduced motion, no animation support or an error the full day shows. |
| `site/privacy.html`, `site/terms.html`, `site/styles.css` | The policy and terms, and the styles they (and 404) use. |
| `site/404.html`, `site/robots.txt`, `site/_headers` | Not-found page, crawler rules, cache and safety headers. |
| `site/assets/img/` | Made by `build_site.py`. Don't edit by hand. |
| `site/assets/fonts/` | IBM Plex Mono for the front page; Instrument Serif and Nunito for the others (SIL Open Font Licence, texts alongside). |
| `site/assets/video/social.mp4` | The link-preview video: the calendar story, 1200×630, looping. Messages plays it in the preview; elsewhere `social.png` shows. Made by `record_social_video.mjs`; re-run it after any change to the scene. |
| `record_social_video.mjs` | Records `social.mp4` from the page itself, frame by frame (`npm install` once; needs ffmpeg). |
| `build_site.py` | Turns marketing captures into site images, exports the current icon master and copies the retained social artwork. |
| `check_site.py` | The site's rules: links, images, claims, weight. Run before a deploy. |
| `wrangler.toml` | Cloudflare Workers settings (static files only). |

## Change it and publish it

```sh
python3 LandingPage/build_site.py      # only after new screenshots (tools/app-store/generate.py)
python3 LandingPage/check_site.py      # must pass
LandingPage/publish.sh                # builds/checks content, then deploys (Wrangler login required)
```

To look at it first: `cd LandingPage/site && python3 -m http.server 8000`.

Current visual identity: IBM Plex Mono, the dimensional yellow mascot, cream/ink/yellow and pastel
scene panels. The earlier editorial-serif concept is historical. `Brand/README.md` and the
current-direction note at the top of `HANDOFF.md` describe the shared website/store identity.
The site builder uses the current icon master and retains the calendar-scene social artwork.

changing those assets. Icon URLs are versioned in the page shells to avoid stale browser caches.

## Blog publishing

The blog is for engineering stories and product development, not a help center. The earlier
Busy-block guide is retained under `content/guides/` and is not published as a blog post.

The public blog is `/blog/`; articles live at `/blog/<filename>/`. RSS is `/blog/feed.xml`.
The blog, about page, feed and sitemap are generated by `build_content.py` using pinned
MIT-licensed markdown-it-py 4.0.0, with HTML disabled. No client framework or CMS is required.
The dependency lock is `build_content.py.lock` (`uv run --locked` respects it).

1. Copy `content/post-template.md` into `content/posts/your-url-slug.md`.
2. Write the title, description, real publication/update dates, category and Markdown body.
   Keep `draft = true` while working. A missing draft flag fails rather than publishing.
   The first paragraph should answer the title's question; use `##` headings, real examples,
   useful internal links and sources for external claims. Never invent testimonials or results.
3. Preview drafts separately:
   `uv run --locked LandingPage/build_content.py --preview --out /tmp/banana-blog-preview`.
   Serve that folder with `python3 -m http.server 8898 --directory /tmp/banana-blog-preview`.
   Preview pages carry noindex and a preview banner. Never deploy the preview folder.
4. When ready, set `draft = false`, set the publication date, and run `LandingPage/publish.sh`.
   The command regenerates only published content in `site/`, validates every page, and deploys.
   Future-dated posts wait until a build on/after their date; there is no background scheduler.
5. Commit the post and generated outputs together. Keep published URLs stable; add a redirect
   for a deliberate rename. Updating a post must use its actual edit date, not a daily build date.

The current byline links to the real Banana team at `/about#team`; add a genuine author profile
before changing the byline. Markdown images currently fail the build so no unsized images slip
in; add image dimensions/template support before publishing inline photos. Text links work.
RSS currently supplies summaries with links to full articles. The preview is local, not authenticated;
only bind a draft server to a trusted interface and stop it when finished.

Checks (run from the repository root):

```sh
uv run --with markdown-it-py==4.0.0 python -m unittest discover -s LandingPage -p test_content.py
uv run --locked LandingPage/build_content.py
python3 LandingPage/check_site.py
# With Wrangler dev running on port 8897; headless, no desktop input:
volta run --node 24.22.1 node LandingPage/check_layout.mjs
```

`check_site.py` includes sitemap coverage, metadata, structured-data parsing, internal anchors,
article links, and the existing claims/image/byte checks. The scene's three JavaScript-inserted
room images now count toward the unchanged home-page byte budgets. This is a byte check,
not a physical frame/input performance result. See `docs/seo/2026-10-27-review.md` for the audit,
remaining account-level work and the recurring content review checklist.
